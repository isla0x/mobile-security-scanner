# 기획 배경 (Planning Notes)

## 컨셉
모바일 앱 보안 셀프체크 툴. 개발자/QA가 APK(또는 디컴파일된 소스)를 넣으면
OWASP MASVS 기준으로 자동 진단 리포트를 만들어주는 서비스.

기존에 MobSF 같은 강력한 오픈소스 도구가 이미 있어서, 차별화 포인트는:
- 비개발자도 이해하기 쉬운 리포트 UX
- 한국 앱스토어 심사 기준에 맞춘 체크리스트 (향후 확장)

## 핵심 기능 범위

1. **정적 분석 (APK 업로드 방식)**
   - AndroidManifest 분석 (권한, exported 컴포넌트, debuggable, allowBackup)
   - 하드코딩된 API 키/시크릿 탐지
   - 취약한 암호화 알고리즘 사용 여부 (MD5, DES, ECB 등)
   - cleartext traffic 허용 여부

2. **동적 분석 (추후 단계)**
   - 실행 중인 앱의 네트워크 트래픽 캡처 → 평문 전송, SSL pinning 여부
   - 로컬 저장소 평문 데이터 탐지

3. **자체 방어력 진단 (역방향 접근)**
   - "내 앱의 루팅 탐지/변조 방지 로직이 얼마나 견고한가"를 진단
   - ⚠️ 우회 코드 자체는 만들지 않음 — 다른 앱의 보안 장치를 무력화하는 데
     악용될 수 있는 로직(탐지 회피 코드)은 이 프로젝트의 범위에서 명시적으로 제외.
     진단은 "취약할 수 있다"는 체크리스트 리포트까지만 제공.

4. **리포트 & 스코어링**
   - MASVS 레벨별 점수, 심각도별 분류(Critical/High/Medium/Low)
   - JSON 리포트 + 웹 대시보드 시각화

## 기술 스택 제안
- 정적 분석: apktool/jadx로 디컴파일 → 룰 기반 스캐너 (현재 프로토타입은 Python 정규식 기반)
- 백엔드: 분석 서버 (디컴파일 + 스캔 처리)
- 프론트: 웹 우선 → 이후 Android 앱(Flutter/RN)으로 확장 (동일 백엔드 API 재사용)

## 타겟 & 수익화
- 1차 타겟: 개인 개발자, 소규모 스타트업 (자체 앱 출시 전 셀프 점검용)
- 확장: 보안 컨설팅 업체/QA팀 대상 B2B 구독 모델

## MVP 개발 순서
1. 정적 분석 엔진 프로토타입 (현재 단계 — `scanner/scanner.py`)
2. 리포트 스코어링 로직 (완료 — MASVS 카테고리별 가중치)
3. 웹 업로드 + 리포트 UI (현재 단계 — `dashboard/dashboard.html`)
4. 동적 분석 파이프라인 추가 (에뮬레이터 + mitmproxy, 인프라 비용 발생 구간)
5. Android 앱 클라이언트 (동일 백엔드 API 호출)

## 프로토타입에서 검증한 것
- 매니페스트 취약점 룰 (exported 컴포넌트, debuggable, cleartext 등)
- 하드코딩 시크릿/취약 암호화 정규식 룰 (7개 카테고리, 24개 룰)
- 오탐 감소: 주석 처리된 코드 자동 제외, `// scanner:ignore` 억제 마커
- JSON 리포트를 그대로 불러와 시각화하는 웹 대시보드 (심각도/카테고리 필터링)

## 파이프라인 연결 검증 (완료)
`scanner/pipeline.py`로 apktool(매니페스트/리소스) + jadx(자바 소스 디컴파일)를
자동 연결해서 실제 APK 파일 하나로 끝까지 돌아가는 것까지 확인했습니다.
실제 오픈소스 APK([openstf/adbkit-apkreader](https://github.com/openstf/adbkit-apkreader)
테스트 픽스처)로 점수 29/100, 8개 이슈(debuggable, allowBackup, 외부 저장소 직접 쓰기 등)를
정상적으로 탐지했습니다.
